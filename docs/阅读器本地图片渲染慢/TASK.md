## 行为与契约

允许变化：本地页的读取方式与解码线程；SpiderDen 下载目录的命名算法（需兼容已有目录）；SpiderDen 进入下载模式的时机
必须保持：未下载画廊的网络加载、H@H 换节点、域名前置回退不变；部分下载的画廊缺页时逐页回退网络；GIF 多帧动画保留；超大图降采样上限不变；已有下载目录里的文件不能丢失或读不到

| 输入或事件 | 预期结果 | 依据 |
| --- | --- | --- |
| 打开已完整下载的画廊并连续翻页 | 页面直接显示，不出现百分比进度圈，主线程不卡顿 | 原因 A |
| 已下载画廊标题超过约 120 字符 | 阅读器读本地文件，不走网络 | 原因 B |
| 下载完成后立即阅读 | 所有页都在下载目录中，没有页落到阅读缓存 | 原因 C |
| 部分下载的画廊翻到缺失页 | 该页回退网络加载并正常显示 | 必须保持 |

原因定位（调研结论，未经真机验证）：

- A 主因：本地页只把 `file://` 地址写进 `imageURLs`（`ehviewer apple/ReaderViewModel.swift:917`），随后 `downloadImageData` 仍走 `URLSession.bytes` 逐字节读取（同文件 :690–717）。`ReaderViewModel` 是 `@MainActor`，所以这个逐字节循环跑在主线程上，预加载的几页都挤在主线程上轮流执行。上游 main 的 4635577 已改为遇到 `isFileURL` 直接读文件并在后台解码
- B 次要原因：`DownloadManager.galleryDirectoryName` 先截断标题再拼 gid（`Packages/EhDownload/Sources/EhDownload/DownloadManager.swift:505`）；`SpiderDen.getGalleryDownloadDir` 先拼 `gid-标题` 再整体截断到 128 字符（`Packages/EhSpider/Sources/EhSpider/SpiderDen.swift:90`）。标题超过约 120 字符时两者不一致：文件写进 SpiderDen 目录，阅读器却去 DownloadManager 目录找，整本走网络。上游 main 仍未修
- C 低概率：`SpiderQueen.init` 用不等待的 `Task` 设置 SpiderDen 为下载模式（`Packages/EhSpider/Sources/EhSpider/SpiderQueen.swift:82`）。如果首批页写盘时它还没执行，这些页会写进阅读缓存，而不是下载目录

修复方式（计划）：

- A：在 `downloadImageData` 入口判断 `isFileURL`，直接读文件，并把读取和降采样一起放到后台执行，完成后再回到主线程写 `cachedImages`；参考上游 4635577 的思路，不整体 cherry-pick
- B：并入 [EH-4](../下载列表分组与排序/TASK.md)：路径改为按 gid 查 `downloadDirname` 索引，索引来自扫描 `.ehviewer`，旧目录按实际目录名记录，无需迁移
- C：SpiderDen 的模式改为在构造时确定，或在 `startDownload` 开头 `await` 设置完成后再派发页面任务
