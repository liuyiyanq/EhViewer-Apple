## 行为与契约

允许变化：设置项文案与说明；单本画廊内获取 pToken 的去重方式
必须保持：全局图片请求并发上限 5（`Packages/EhCore/Sources/EhSettings/EhRateLimiter.swift`）不放宽；暂停、删除、恢复的语义不变；下载顺序仍是队列先进先出

| 输入或事件 | 预期结果 | 依据 |
| --- | --- | --- |
| 「并发线程」设为 3，下载一本画廊 | 同一时刻最多 3 页在下载 | `SpiderQueen.startDownload` 的 TaskGroup |
| 同时加入两本画廊 | 当前实现下第二本显示"等待中"，直到第一本完成 | `DownloadManager.processQueue` 只有一个 `activeTask` |
| 下载开始或跨入新的 20 页区段 | 同一个详情页只请求一次 | 修复后行为，见修复方式第 2 项 |

原因定位（调研结论，未经真机验证）：

- 画廊级串行是写死的设计：`processQueue` 用 `guard activeTask == nil` 保证同一时刻只下一本（`Packages/EhDownload/Sources/EhDownload/DownloadManager.swift:325`）。同文件 :36 的 `maxConcurrent = 1` 是没人用的常量
- 「并发线程」设置（`ehviewer apple/SettingsView.swift:703`，范围 1–5，默认 3）只控制单本画廊内同时下载的页数（`Packages/EhSpider/Sources/EhSpider/SpiderQueen.swift:136-159`），代码上是有效的
- 效率损耗：`getPToken` 不去重（`SpiderQueen.swift:381`），开始下载和每跨 20 页时，多个并发任务会重复请求同一个详情页，占用全局的 5 个请求名额

修复方式（计划）：

1. 设置项改名为「单本并发页数」，并加一行说明：画廊按队列逐本下载
2. pToken 获取按详情页号去重：同一详情页只请求一次，其余任务等待该请求结果
3. 删除未使用的 `maxConcurrent = 1` 常量
