## 行为与契约

允许变化：分组的判定条件；阅读存页时写 .ehviewer 的时机；解散分组的提示
必须保持：画廊身份只认 .ehviewer 中的 gid（EH-4 决策 5）；用户在「文件」App 中自建的文件夹仍识别为分组；已有画廊目录不改名、不移动

| 输入或事件 | 预期结果 | 依据 |
| --- | --- | --- |
| 根目录下有只含 `%08d.ext` 图片、没有 .ehviewer 的目录 | 不显示为分组 | 修复方式 1 |
| 阅读一本在下载列表中但还没开始下载的画廊 | 新建的目录同时写入 .ehviewer，不会变成分组 | 修复方式 2 |
| 上述画廊之后开始下载或继续阅读 | 继续使用同一目录，已存的页不重下 | 现有逻辑 |
| 用户自建文件夹里只有非画廊文件，点解散 | 提示「分组里没有可移出的画廊，目录中的其他文件已保留」 | 修复方式 3 |
| 空的自建文件夹点解散 | 目录被删除，分组消失 | 现有逻辑 |

原因定位（已在代码中确认）：

- EH-4 规定根目录下没有 .ehviewer 的子目录就是分组（`DownloadManager.directoryLayout`）
- EH-6 让下载列表中的画廊在阅读时一律存页。还没开始下载的画廊此时才建目录：`saveWhileReading` 写了图片，但写 .ehviewer 的逻辑在 `registerReadingSyncTaskIfNeeded` 里，画廊已在下载列表中时提前返回，于是目录只有图片
- 这类目录被识别成分组，组内没有画廊，显示「0 本」；画廊真正开始下载时 `executeDownload` 会补写 .ehviewer，所以等待或暂停的画廊会一直挂着
- 解散只移动含 .ehviewer 的子目录，最后只在目录为空时删除；这类目录没有子目录、只有图片，于是什么都不做也不报错

修复方式：

1. 分组判定：没有 .ehviewer 且目录里没有 `%08d.ext` 页面图片，才算分组（`SpiderInfoFile.isGroupDirectory`）。已有的这类目录随即不再显示为分组；它们仍按旧规则 `gid-标题` 被找到，阅读和下载照常使用
2. 阅读存页：`saveWhileReading` 新建或写入目录时，目录里没有 .ehviewer 就先写一份；`registerReadingSyncTaskIfNeeded` 只负责登记任务
3. 解散：没有移出任何画廊、目录又因为有其他文件而保留时，报错提示
