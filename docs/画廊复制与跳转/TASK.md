# EH-5 画廊标题与评论复制、评论链接跳转、下载页封面跳转

目标：在线画廊详情页可以复制标题和评论；点评论里的画廊链接直接在 App 内打开对应画廊；下载页点封面打开该画廊的详情页
范围与不做项：涉及画廊详情页头部与评论区、全部评论页、下载列表行、画廊链接解析；不做评论里图片页链接（`/s/`）的跳转，这类链接和其他外部链接一样用系统浏览器打开；不改评论发表、投票、编辑
事项类型与 TAPD 关键字：无 TAPD，本地编号 EH-5
相关文档：[EH-4 下载列表分组与排序](../下载列表分组与排序/TASK.md)（同样修改下载列表行，实现时注意合并）；执行顺序与跨任务约束见 [本期执行计划](../PLAN.md)

## 行为与契约

允许变化：详情页标题与评论的交互和渲染方式；下载列表行封面的点击行为
必须保持：评论默认显示前 2 条、每条最多 5 行；评论投票和编辑可用；下载列表行点击其他区域仍打开阅读器；批量选择模式下点封面仍是选中

| 输入或事件 | 预期结果 | 依据 |
| --- | --- | --- |
| 长按详情页标题 | 弹出菜单：复制标题、复制日文标题（有日文标题时）、复制画廊链接 | 修复方式第 3 项 |
| 长按一条评论 | 弹出菜单：复制评论（纯文本，保留换行） | 修复方式第 4 项 |
| 点评论里的 `e-hentai.org/g/…` 或 `exhentai.org/g/…` 链接 | 在当前页面栈中推入该画廊详情页，标题和封面正常显示 | 修复方式第 1、2、4 项 |
| 点评论里的其他链接 | 用系统浏览器打开 | 范围 |
| 下载页点某本画廊的封面 | 推入该画廊详情页 | 修复方式第 5 项 |
| 下载页点行内其他区域 | 仍打开阅读器 | 必须保持 |

现状（读代码得出，未经真机验证）：

- 标题没有任何复制入口：详情页头部是普通 `Text`（`ehviewer apple/GalleryDetailView.swift:209`）
- 评论没有复制入口，而且链接丢失：详情页的评论预览（同文件 :685，预处理在 :916-927）和全部评论页（`ehviewer apple/GalleryCommentsView.swift:126`）都用正则删掉全部 HTML 标签。`<a href>` 的地址丢了，只剩链接文字；`<br>` 被删后多行评论会连成一行；`&amp;` 这类实体没有解码
- 已有画廊链接的识别和打开逻辑：剪贴板检测（`ehviewer apple/RootView.swift:411` 的正则）发出通知，`ehviewer apple/MainTabView.swift:134`、`:181` 用 `GalleryInfo(gid:token:)` 打开详情页，可以复用
- 只带 gid 和 token 打开详情页时，头部可能是空的：头部的标题、封面、上传者都读的是传入的 `gallery`（`GalleryDetailView.swift:196-215`），没有改用加载后的 `vm.detail?.info`。剪贴板打开画廊时应该已有这个问题
- 下载列表整行是一个按钮，点击打开阅读器（`ehviewer apple/DownloadsView.swift:707`）；`DownloadTask.gallery` 中已有数据库里存的 gid 和 token，封面跳转不需要读 `.ehviewer`

修复方式（计划）：

1. 画廊链接解析：在 `EhURL` 增加一个解析函数，从 URL 中取出 gid 和 token（支持 e-hentai 和 exhentai、http 和 https、末尾带不带 `/`）；剪贴板检测改用它
2. 详情页头部的标题、封面、上传者优先用加载后的 `vm.detail?.info`，没有时再用传入的 `gallery`
3. 标题复制：标题加长按菜单（复制标题、复制日文标题、复制画廊链接）
4. 评论渲染：在现有预处理位置把评论 HTML 转成带链接的 `AttributedString`（`<br>` 转换行、`<a href>` 转链接、解码实体、去掉其他标签），详情页和全部评论页共用；每条评论加长按菜单「复制评论」；用 `OpenURLAction` 拦截链接，画廊链接在 App 内推入详情页，其他链接交给系统
5. 下载页封面：封面单独响应点击，推入 `GalleryDetailView(gallery: task.gallery)`；行内其他区域保持打开阅读器；批量选择模式下封面点击仍是选中
